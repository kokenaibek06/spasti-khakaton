# Что это за проект и что с ним делать

Нужно было написать программу, которая переносит учебный хакатон в другое здание.
Программа должна выбрать подходящую площадку, составить новое расписание и сообщить
его участникам. При этом она обязана дождаться подтверждения дорогой брони,
продолжить работу после сбоя и защититься от опасных указаний из писем.

Код уже написан. Исходные данные и проверяющие файлы сохранены без изменений.
В папке `runs-live/` лежит полный успешный прогон с настоящей моделью OpenAI
`gpt-5.4-mini`. Все пять сценариев и дополнительные 43 теста прошли.
Изменённые данные также проверены с настоящей моделью: `runs-live-variant/`.
Проверки без модели сохранены отдельно в `runs/` и `runs-variant/`.

## Как запустить у себя

Проект уже проверен с настоящей моделью. В архиве ключа нет. Если запускаете
проект на другом компьютере, добавьте свой действующий ключ OpenAI локально.

1. Откройте терминал в папке этого проекта.
2. Выполните `uv sync --locked`.
3. Скопируйте `.env.example` в `.env` и впишите ключ в `OPENAI_API_KEY`.
   Ключ хранится только у вас; в чат его отправлять не нужно.
4. Запустите `uv run python evals/graders.py --run-all --out runs-live`.
5. Проверьте, что все строки сценариев показывают `УСПЕХ (PASS)`.

Если ключа пока нет, можно проверить программу так:

```bash
MODEL_PROVIDER=offline uv run python evals/graders.py --run-all --out runs
```

Эта команда предназначена для Bash или zsh на macOS / Linux. Вариант для
PowerShell и подробные команды каждого сценария находятся в `README.md`.

## Что сдавать

Сдаётся git-репозиторий проекта: исходники, навык в папке `skills/`, инструкция
`README.md`, файл зависимостей и результаты проверок. В готовой папке уже создан
локальный git-репозиторий. Публикация на GitHub не выполнялась.

Если повторяете запуск, выполните
`uv run python scripts/summarize_budget.py runs-live`: программа сама соберёт
токены и стоимость в `runs-live/BUDGET.md`. Добавьте результаты `runs-live`
в репозиторий. В текущей версии отчёты уже сохранены и описаны в README. Эти числа нельзя заменить
данными режима offline или тестового сервера.

## Как понимать основные файлы

- `agent.py`: управляет работой и запоминает, на каком этапе программа остановилась.
- `mcp_server.py`: выполняет действия и проверяет, разрешены ли они.
- `planner.py`: подбирает расписание без пересечений.
- `model_client.py`: подключает ИИ-модель и считает её использование.
- `skills/relocate-hackathon/SKILL.md`: инструкция для задачи переноса.
- `state.json`: сохранённое состояние конкретного запуска.
- `journal.jsonl`: журнал действий для разбора ошибок.

Ключевой принцип: программа сверяет реальные файлы результата перед статусом
`done`. Одного ответа модели «всё готово» для успеха недостаточно.
